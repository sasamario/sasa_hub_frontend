# ハイドレーション(hydration)

SSR(サーバーサイドレンダリング)とセットで理解する概念。Nuxtは基本的に2段階で
ページを組み立てる。

1. **サーバー側(Node.js)**でVueコンポーネントを実行し、静的なHTMLを組み立てて
   ブラウザに送る。この時点のHTMLは見た目はできているが、まだイベントリスナーも
   付いていない「ただの静的なHTML」。
2. ブラウザがそのHTMLを受け取った後、**もう一度同じVueコンポーネントのコードを
   ブラウザ側で実行**し、すでに存在するHTML要素に「クリックしたら反応する」などの
   命を吹き込む(インタラクティブにする)。

この2番目の工程が**ハイドレーション**(hydration = 「水を与える、潤す」の意味)。
すでにある乾いた(静的な)HTMLに命を吹き込むイメージ。

## なぜ「不一致」が起きるか

ハイドレーションは、「サーバー側で作ったHTMLと、ブラウザ側で作ろうとしているHTMLが
完全に一致していること」を前提にしている。一致していれば、Vueは既存のDOMに
イベントリスナーなどを紐付けるだけで済み効率的。

しかし、サーバー側とブラウザ側で**実行結果が変わってしまう処理**(実行環境依存の
処理)を挟むと、両者の出力が食い違い、Vueが警告を出す。

```
Hydration completed but contains mismatches
```

Vueは一応このズレを検知して修正してくれるが、本来しなくていい余計な処理が
発生している状態であり、根本原因を直すべき。

## 実際に遭遇した原因: `.toLocaleDateString()`

```vue
<p>{{ periodRange.from.toLocaleDateString() }}</p>
```

`.toLocaleDateString()`は**実行環境のロケール設定に依存**する。サーバー側
(Dockerコンテナ内のNode.js)とブラウザ側で、この結果が異なる形式になり、
ハイドレーション不一致の原因になった。

対応: この表示部分を`<ClientOnly>`で囲み、**サーバー側での描画自体をスキップ**
することで、「サーバー版とブラウザ版を比較して一致させる」という工程自体を
不要にした。`<ClientOnly>`の詳細は[client-only.md](./client-only.md)参照。

## 他にも実行環境依存でズレやすい処理の例

- `Math.random()`(フェーズ3のモックデータで実際に遭遇。[setup.md](../setup.md)参照)
- `new Date()`(呼び出すタイミングでサーバーとクライアントの時刻がわずかにズレる)
- ブラウザ専用API(`window`, `localStorage`など)に依存する処理
