# ディレクトリ構成(規約フォルダ一覧)

Nuxtは「決まった場所にファイルを置くだけで機能する」規約(Convention over Configuration)を
採用している。`pages/`や`layouts/`と同様に、他にも特別に認識されるフォルダがある。

参考: [Nuxt公式 - Directory Structure](https://nuxt.com/docs/4.x/guide/directory-structure/nuxt)

## `app/`配下(フロントエンド寄り)

| フォルダ | 役割 |
|---|---|
| `pages/` | ファイルベースルーティング。詳細: [routing.md](./routing.md) |
| `layouts/` | 共通レイアウト。詳細: [routing.md](./routing.md) |
| `components/` | 置くだけで`import`無しにテンプレート内でタグとして使えるVueコンポーネント |
| `composables/` | 置くだけで自動インポートされる「状態・ロジックの再利用可能な関数」(`use〇〇`という命名が慣習) |
| `plugins/` | アプリ起動時に自動実行される初期化処理。サードパーティライブラリの登録などに使う。詳細: [plugins.md](./plugins.md) |
| `middleware/` | ページ遷移時に割り込ませる処理(認証チェックなど) |
| `utils/` | 置くだけで自動インポートされる、状態を持たない汎用関数 |
| `assets/` | ビルド時に処理される画像・CSSなど(Webpack/Viteの処理対象) |
| `app.vue` | 大元のコンポーネント。詳細: [routing.md](./routing.md) |
| `app.config.ts` | ビルド時に確定する公開設定値(実行時に変更されない値) |
| `error.vue` | エラー画面のカスタマイズ用 |

## トップレベル(バックエンド寄り・その他)

| フォルダ | 役割 |
|---|---|
| `public/` | そのまま配信される静的ファイル(ビルド処理を通さない) |
| `server/` | Nuxt自体が持つサーバーサイド処理(APIルートなど)。本プロジェクトでは
  バックエンドを別リポジトリで持つため、基本的に使わない想定 |
| `content` | Nuxt Contentモジュール用(今回未導入) |
| `modules` | プロジェクト独自のNuxtモジュールを置く場所 |

## `composables/` と `utils/` の違い(補足)

どちらも「置くだけで自動インポートされる」点は同じだが、想定している中身が異なる。

- `composables/`: Vueの`ref`/`computed`などを使い、**状態を持つ**ロジック(例: `useAuth`)
- `utils/`: 状態を持たない、**入力から出力を計算するだけの純粋な関数**(例: 今回の`resolvePeriodRange`)

## 新しいファイル追加時に開発サーバーの再起動が必要なケース

Nuxtの開発サーバーは、既存ファイルの変更はホットリロードで即座に反映してくれるが、
**規約フォルダに新規ファイルを追加した直後は、ホットリロードだけでは認識されず、
開発サーバーの再起動が必要になることがある**。特に`plugins/`は要注意
(実際に`chart.client.ts`を新規追加した際、再起動するまで登録処理が反映されなかった)。

- 症状: ファイルを追加したのに機能が反映されない、原因不明のエラーが出る
- 対応: `docker compose up`を一度Ctrl+Cで止めて、再度起動し直す
