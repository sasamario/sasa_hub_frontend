# scoped CSSと`:deep()`

`<style scoped>`は、Nuxt固有ではなく**Vue(単一ファイルコンポーネント)自体の機能**。

## 背景・存在意義

CSSのクラス名は本来、ページ全体で1つの名前空間を共有する(グローバル)。
コンポーネント単位で開発を行うフレームワークでは、多数の小さなコンポーネントを組み合わせて
画面を作るため、別々のコンポーネントで同じクラス名(例: `.title`)を使うと、
意図せずスタイルが衝突・混ざってしまう可能性がある。

`scoped`は、この「クラス名の衝突」を防ぐための仕組み。コンポーネントごとに
目印の属性を自動で付与することで、クラス名自体は単純なまま(BEMのような
命名規則で頑張って一意にする必要がない)、スタイルの効く範囲だけを
自動的にそのコンポーネント内に閉じ込めてくれる。

## `scoped`の仕組み

`<style scoped>`を使うと、Vueはコンパイル時に「そのコンポーネントのテンプレート内の要素」に
目印となる属性(例: `data-v-abc123`)を自動的に付ける。書いたCSSセレクタも、裏側では
「その属性を持つ要素にだけ」効くように変換される。

```css
/* 自分で書いたCSS */
.foo { color: blue; }

/* 実際にはこう変換されて動く */
.foo[data-v-abc123] { color: blue; }
```

これにより、あるコンポーネントで書いたスタイルが他のコンポーネントに漏れ出さない。

## 子コンポーネントの中身には効かない

別のコンポーネント(例: `NuxtLink`)が内部で描画する要素は、**自分のテンプレートの一部ではない**ため、
目印の属性が付かない。そのため、通常のscopedスタイルのセレクタはマッチしなくなる。

## `:deep()`で貫通させる

`:deep(セレクタ)` と書くと、「このセレクタの手前側(祖先要素)は自分の目印を要求するが、
実際にマッチさせたい要素自体は目印の有無を問わない」という変換になる。

```css
/* 書いたコード */
.nav :deep(.router-link-exact-active) { color: blue; }

/* 実際の変換イメージ */
.nav[data-v-abc123] .router-link-exact-active { color: blue; }
```

「`.nav`(自分のテンプレート内の要素)の中にある`.router-link-exact-active`(どのコンポーネントが
描画したものでもよい)」という意味になり、子コンポーネントが描画した要素にもスタイルが届く。

## 使いどころ

- 子コンポーネント(`NuxtLink`など)がレンダリングした要素にスタイルを当てたい時
- ライブラリ製コンポーネントの内部要素の見た目を、自分のコンポーネント側から調整したい時
