## 3. 共通設計方針

### 3.1 データ設計の基本原則

- **生データ(明細)を保存し、集計は参照時に行う。**
  事前に集計した値は基本的に保存せず、ダッシュボード表示時にクエリで算出する。
  これにより任意の切り口(月別・週別・種別別など)で後から集計でき、
  同期時の重複防止も一意キーで素直に実装できる。(ADR-0001)

### 3.2 ソース別テーブル方針

- 活動データはソース(GitHub / Qiita / 手動記録)ごとにテーブルを分ける。
  各ソースは持つ属性が異なるため、無理に単一テーブルへ統合しない。
- ダッシュボードでの集計・表示時に各テーブルを統合して扱う。

### 3.3 共通カラム: 日時の役割分担

全テーブルで日時カラムの意味を統一する。

| カラム | 意味 | 管理方法 | 対象 |
|---|---|---|---|
| `activity_date` | その活動が行われた日時。集計・並び替えの軸 | 各ソースから取得しセット | 活動系テーブル共通 |
| `created_at` | レコードをDBに初めて保存した日時 | Prisma `@default(now())` で自動 | 全テーブル |
| `updated_at` | レコードが最後に更新された日時 | Prisma `@updatedAt` で自動 | 全テーブル |
| `synced_at` | 外部APIから最後にデータを取得した日時(データの鮮度) | 同期処理で明示的にセット | API連携テーブルのみ |

補足:
- `activity_date` はソース横断の共通名とし、中身(何の日時か)はソースごとに定義する。
  - GitHub(commit): コミット日時 / GitHub(PR): マージ日時 / Qiita: 投稿日時
- `updated_at` と `synced_at` は意味が異なる。同期を実行しても取得値が前回と同じ場合、
  レコードは変化しないため `updated_at` は動かないが、`synced_at` は更新したい。
  よって両者を別カラムとして持つ。

## 4. データモデル(確定分)

### 4.1 github_activities(GitHub活動)

コミットとPRの両方を1テーブルに `type` で区別して保存する。
明細を保存し、コミット数・PR数などは集計時に算出する。(ADR-0002)

| カラム | 型 | NULL | 説明 |
|---|---|---|---|
| id | 主キー(自動採番) | 不可 | 内部ID |
| type | enum(commit / pull_request) | 不可 | 種別 |
| external_id | 文字列 | 不可 | コミットSHA or PR番号。一意キーの一部 |
| repository | 文字列 | 不可 | owner/repo 形式。一意キーの一部 |
| title | 文字列 | 不可 | コミットメッセージ or PRタイトル |
| url | 文字列 | 不可 | 該当ページへのリンク(一覧表示用) |
| activity_date | 日時 | 可 | commit日時 or PRマージ日時。未マージPRはNULL |
| created_at | 日時 | 不可 | DB保存日時(自動) |
| updated_at | 日時 | 不可 | レコード更新日時(自動) |

- 一意制約: `(type, repository, external_id)` の3点で一意
- 同期は「追加のみ」。一意キーで取り込み済みを判定して重複を防ぐ。
- 未マージPR(activity_date = NULL)はデータとして保持するが、集計対象からは除外する。
  一覧表示での見せ方は実装フェーズで詳細化する。
- コミット数とPR数は別指標として扱い、単純合算による二重カウントを避ける。

### 4.2 qiita_articles(Qiita記事)

1記事1レコードで最新値のみ保持する。同期のたびに upsert(存在すれば更新・
なければ挿入)で最新のいいね数・PV数等に上書きする。推移(履歴)は保持しない。(ADR-0003)

| カラム | 型 | NULL | 説明 |
|---|---|---|---|
| id | 主キー(自動採番) | 不可 | 内部ID |
| external_id | 文字列 | 不可 | Qiita記事ID。一意キー |
| title | 文字列 | 不可 | 記事タイトル |
| url | 文字列 | 不可 | 記事URL(一覧表示用) |
| activity_date | 日時 | 不可 | 記事の投稿日時(created_at)。集計・並び替えの軸 |
| likes_count | 整数 | 不可 | いいね数(同期時に上書き) |
| stocks_count | 整数 | 不可 | ストック数(同期時に上書き) |
| page_views_count | 整数 | 可 | PV数(記事ごとの個別API取得。失敗時はNULL) |
| synced_at | 日時 | 不可 | 最後にQiitaから取得した日時(鮮度) |
| created_at | 日時 | 不可 | DB保存日時(自動) |
| updated_at | 日時 | 不可 | レコード更新日時(自動) |

- 一意キー: `external_id`(Qiita全体で一意なため単独で可)
- 同期は upsert。GitHub(追加のみ)と実装が異なる点に注意。
- PV数は記事一覧APIに含まれず、記事IDごとの個別APIコールが必要。
  Qiita APIのレート制限に配慮する(ページング・スリープ等)。
- タグはMVPでは保持しない(将来、多対多で追加可能)。
