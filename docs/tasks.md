# 実装タスク(フロントエンド)

本リポジトリ(Nuxt 4 フロントエンド)のMVP実装タスク。
チェックリストで管理し、着手・完了時に更新する。大きなタスクは着手前にサブタスクへ分解する。

> 進め方は CLAUDE.md の「進め方の方針」に従う(一度に大量に書かず、方針を相談してから実装)。
> バックエンドの作業は本リストに含めない(別リポジトリで管理)。

## フェーズ1: 環境構築

- [x] Nuxt 4 プロジェクトの初期化
- [x] Docker で開発環境を起動できるようにする(Dockerfile / compose)
- [x] Lint / Formatter の設定(コーディング規約)
- [x] バックエンドAPIの接続先(ベースURL)を環境変数で持つ仕組み
- [x] 初回セットアップ手順を `docs/guides/setup.md` に記録する

## フェーズ2: 共通レイアウト

- [x] 共通レイアウト(左サイドメニュー + 右メインエリア)の作成
- [x] サイドメニュー項目(ダッシュボード / GitHub詳細)と現在地ハイライト
- [x] ルーティング設定(ダッシュボード / GitHub詳細の2ページ)
- [x] ページ追加の手順を `docs/guides/add-page.md` に記録する

## フェーズ3: ダッシュボード画面(モックデータで先行実装)

バックエンドが別リポジトリで未着手のため、`architecture.md`のAPI仕様に沿った
モックデータで画面を先に作り込む。本物のAPI接続はフェーズ5で行う。

- [x] 期間セレクタ(直近1年 / 6ヶ月 / 3ヶ月 / 1ヶ月、デフォルト1年)
- [x] 同期ボタン(同期APIの呼び出し、実行中の状態表示)
- [x] GitHubサマリーカード(コミット総数・PR総数、クリックでGitHub詳細へ)
- [x] Qiitaサマリーカード(記事数・合計view数・合計LGTM数)
- [x] コミット推移グラフ(週別固定・リポジトリ選択式・デフォルト「すべて(合計)」)
- [x] リポジトリ別コミット数の円グラフ(0%のリポジトリも凡例に表示)
- [x] 期間変更時にGitHubエリア(カード・グラフ)が連動して更新される
      (Qiitaは最新値のみ保持する設計のため、期間セレクタとは非連動。architecture.md 5.2参照)

## フェーズ4: GitHub詳細画面(モックデータで先行実装)

こちらも同様にモックデータで先行実装する。

- [ ] 画面見出し + 期間セレクタ
- [ ] コミット推移グラフ(粒度切り替え 日/週/月・リポジトリ選択式)
- [ ] 活動一覧(コミット/PRを時系列でフラット表示)
- [ ] 一覧のフィルタ(リポジトリ絞り込み / 種別絞り込み)
- [ ] 「さらに読み込む」(カーソル方式のページング)
- [ ] 一覧の各行クリックで GitHub の該当ページを開く

## フェーズ5: API呼び出しの基盤・バックエンドとの接続

バックエンドの準備が整い次第、モックを本物のAPI呼び出しに差し替える。

- [ ] APIクライアントの共通処理(ベースURL・エラーハンドリングの土台)
- [ ] 期間パラメータ(from/to)の共通の扱いを決める
- [ ] フェーズ3・4で使ったモックデータを実際のAPI呼び出しに差し替える
- [ ] API呼び出し追加の手順を `docs/guides/add-api-client.md` に記録する
