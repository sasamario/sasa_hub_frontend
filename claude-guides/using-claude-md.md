# CLAUDE.md の使い方

> このガイドは Claude Code を使う上での汎用知識です。特定プロジェクトに依存しないため、
> 他の開発でも参考にできます。

## CLAUDE.md とは

Claude Code がセッション開始時に **自動で読み込む** プロジェクトの指示書。
Claude Code はこの会話の外の記憶を持たないため、CLAUDE.md が
「毎回必ず最初に共有される前提」になる。ここにプロジェクトの要点や進め方を書いておくと、
セッションのたびに一から説明せずに済む。

## 最重要の原則: 薄く保つ

CLAUDE.md は **毎回のセッションで毎回読み込まれる**。ここに情報を詰め込みすぎると、
毎回無駄なものを読むことになり、かえって焦点がぼやける。

- **全セッションで必要になる要点だけ** を書く。
- 詳細は別ドキュメント(設計書など)に置き、CLAUDE.md からは参照させる。
- 「その作業のときだけ必要な情報」は書かない。必要なときに該当ドキュメントを読ませる。

## 何を書くとよいか

- プロジェクトが何か(1〜2行)、技術スタック
- **進め方の方針**(どう振る舞ってほしいか。ここが一番効く)
  - 例: 一度に大量に書かない / 実装前に相談する / 日本語で応答する
- コーディング規約・命名のルール(あるなら)
- よく使うコマンド(ビルド・テスト・起動など)
- 設計ドキュメントへの参照(下記)
- 触ってはいけない領域、注意点

## 何を書かないほうがよいか

- 特定の作業でしか使わない詳細な手順(→ 別の手順書に置く)
- 長大な設計内容そのもの(→ 設計書に置いて参照させる)
- 一度きりの指示(それはその場でチャットに書けばよい)

## 別ドキュメントの参照のさせ方

CLAUDE.md 内から `@パス` の形で他のファイルを参照させられる。
これにより CLAUDE.md 本体を薄く保ちつつ、必要なときに詳細へ誘導できる。

例:
```
プロジェクトの設計は以下を参照:
- 要件定義: @docs/requirements.md
- 基本設計: @docs/architecture.md
```

## 迷ったときの考え方

「この情報は “毎回” 必要か?」を自問する。
- 毎回必要 → CLAUDE.md に書く(簡潔に)
- ときどき必要 → 別ドキュメントに書いて参照させる
- 一度きり → その場のチャットで指示する
