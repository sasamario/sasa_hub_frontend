# tasks.md の使い方

> このガイドは Claude Code を使う上での汎用知識です。他の開発でも参考にできます。

## tasks.md とは

実装タスクを **チェックリスト** で管理するファイル。
「これから何をやるか」「どこまで終わったか」を一覧できる状態にしておくことで、
セッションをまたいでも作業を再開しやすくなる。

CLAUDE.md が「プロジェクトの前提」なら、tasks.md は「作業の進行表」。役割が違う。

## なぜ使うのか

- **セッションをまたげる。** Claude Code は前回の記憶を持たない。tasks.md を見れば
  「前回どこまでやって、次は何か」がすぐ分かる。
- **進捗が見える。** チェックが増えていくと達成感があり、個人開発の挫折を防ぎやすい。
- **作業を渡しやすい。** 「次は "○○" のタスクをやろう」と、粒度の揃った単位で依頼できる。

## 書き方

Markdown のチェックボックスで書く。Claude Code は完了時にチェックを更新できる。

```markdown
## フェーズ1: 共通レイアウト

- [ ] 共通レイアウトの作成
- [x] ルーティング設定 ← 完了したものはチェック
```

## 使い方のコツ

1. **大きなタスクは着手前に分解する。** 「ダッシュボードを作る」は大きすぎる。
   カード・グラフ・期間セレクタ…と小さく割ると、一つずつ確実に進められる。
2. **依存順に並べる。** 環境構築 → 土台 → 各機能、のように前提が先に来る順にする。
3. **完了したらすぐチェックを更新する。** 状態と実態がずれると信頼できなくなる。
4. **保留・今後の項目も残す。** やらないと決めたものも「保留」として書いておくと、
   後で「これはなぜ後回しにしたか」を思い出せる。
5. **セッション開始時に tasks.md を見てもらう。** 「まず tasks.md を見て、次のタスクから
   進めよう」と伝えると、前回の続きにスムーズに入れる。

## CLAUDE.md との連携

CLAUDE.md に「タスクは tasks.md で管理する」「着手・完了時にチェックを更新する」と
書いておくと、Claude Code がこのファイルを自然に使ってくれる。
