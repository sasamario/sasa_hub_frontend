# Claude / Claude Code とうまく進めるコツ

> このガイドは Claude / Claude Code を使う上での汎用知識です。他の開発でも参考にできます。

## 協働の基本姿勢

Claude は強力だが、指示なしに任せると「動くけれど自分が理解できていない」状態に
なりやすい。特に学習目的では、**主導権を持って一緒に進める** 意識が大事。
以下は、そのための具体的なコツ。

## 進め方のコツ

### 1. 方針を先に合意してから実装させる

いきなり「作って」ではなく、まず「どう作るつもりか(設計・使うもの・構成案)」を
説明させ、納得してから実装に入る。手戻りが減り、理解も深まる。

### 2. 一度に大量に書かせない

大きな塊を一気に出されると、レビューも理解も追いつかない。
小さな単位に分けて、一つずつ進める。CLAUDE.md にこの方針を書いておくと徹底されやすい。

### 3. 前提・専門用語を明示する / 分からなければ聞き返す

Claude は前提を補って進めることがある。認識をそろえるため、前提は明示する。
逆に、Claude が使った用語や判断が分からなければ **遠慮なく「それは何?」と聞く**。
用語の意味、なぜその選択か、代替案は何か——聞くほど理解が深まる。

### 4. 鵜呑みにせず、指摘して修正させる

Claude は間違えることもある。おかしいと思ったら指摘してよい。
「その設計だとこういう場合に困るのでは?」といった問いは、より良い設計につながる。
自分の考え(例: 「ここはこう持ちたい」)を伝えると、それに沿って調整される。

### 5. 決めた理由を記録に残す

会話で決めたことは流れて消える。重要な判断は ADR や設計書に残す。
「今の内容をまとめておきますか?」と Claude に確認させる運用にすると、まとめ漏れが減る。

### 6. 選択肢と根拠を出させる

「A と B どちらがいい?」と迷ったら、それぞれの利点・欠点・おすすめと理由を出させる。
決めるのは自分。判断材料をそろえる作業を Claude に任せると、納得して選べる。

## 設計フェーズと実装フェーズの使い分け

Claude には大きく2つの使い方がある。目的で使い分けるとよい。

### チャットの Claude(壁打ち・設計向き)

- 要件の整理、設計の相談、選択肢の比較、ドキュメント作成に向く。
- 図(ワイヤーフレーム等)を交えた検討もできる。
- **実装に入る前の「何を・どう作るか」を固める段階** で力を発揮する。

### Claude Code(実装向き)

- 実際のリポジトリ上でファイルを作成・編集し、コマンドを実行できる。
- コードを書く・直す・動かす **実装の段階** で使う。
- CLAUDE.md / tasks.md / 設計ドキュメントを読ませて、前提を共有した状態で進める。

### 典型的な流れ

1. チャットの Claude で要件・設計を固め、ドキュメント(requirements / architecture / ADR)を作る
2. 引き継ぎ用に CLAUDE.md と tasks.md を用意する
3. 別セッションの Claude Code で、それらを読ませながら実装を進める
4. 実装中に得た手順・知見は guides / claude-guides に記録する

## まとめ

主導権は自分が持つ。方針を合意し、小さく進め、分からなければ聞き、判断は記録する。
Claude は「代わりに作る道具」ではなく「一緒に考えて手を動かすパートナー」として使うと、
学習目的とも噛み合う。
